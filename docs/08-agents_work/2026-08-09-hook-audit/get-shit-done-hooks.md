# get-shit-done Hook Library — Audit

**Source:** `~/VibeCoding/_reference/harness/gsd-build_get-shit-done/` (external reference repo, read-only)
**Scope:** every executable hook file under `hooks/` (13 files) + its two support-library files under `hooks/lib/` + the build script that publishes hooks to `hooks/dist/` (`scripts/build-hooks.js`) — 16 files total, all examined.
**Wiring source:** no static `settings.json`/`hooks.json` template exists in the repo. Wiring is computed programmatically in `bin/install.js` (11,376 lines) around lines 9240–9614, which builds the `settings.hooks.<EVENT>` entries at install time. All "wired to" claims below are read directly from that code (matcher, event name, timeout), not inferred from filenames.
**Judged against Beamix's stack:** bash + node, macOS/darwin, git worktrees, Next.js/TypeScript monorepo with pnpm, and — since these are Claude Code hooks, not application code — Beamix's own `.claude/` multi-agent harness (CEO → C-suite → workers, `.claude/memory/*.md`, `docs/08-agents_work/`) is the real port target.

## Patterns worth stealing

1. **Token-walk git-subcommand classifier** (`hooks/lib/git-cmd.js`) — handles `-C path`, env-prefix, `--flag=value`, and full-path `git` invocations that a naive `^git\s+commit` regex misses. Directly reusable for any Bash-matcher hook that needs to gate on a specific git subcommand (e.g. enforcing Beamix's own `feat(scope): description` commit convention).
2. **Structured JSON hook output with a typed `code`/`decision` field, not just prose** — `gsd-validate-commit.sh` emits `{"decision":"block","code":"CONVENTIONAL_COMMITS_VIOLATION","reason":"..."}`; `gsd-phase-boundary.sh` emits `{planning_modified: true, file_path: ...}`. Lets tests/downstream logic assert on a stable identifier instead of grepping free-form text.
3. **Two-point defense-in-depth prompt-injection scanning** — one hook scans content *about to be written* (`gsd-prompt-guard.js`, PreToolUse), a second scans content *just ingested* via Read (`gsd-read-injection-scanner.js`, PostToolUse) with an additional pattern set specifically targeting instructions engineered to survive context-compaction/summarization.
4. **Runtime self-detection to avoid redundant advisories** — `gsd-read-guard.js` checks `session_id`/`CLAUDE_CODE_ENTRYPOINT`/etc. to detect "this is native Claude Code" (which already enforces read-before-edit) and silently no-ops rather than issuing advice the runtime already gives for free.
5. **Debounced, severity-escalating budget monitor via a bridge file** — the statusline hook (`gsd-statusline.js`) writes a small per-session JSON file every render; a separate PostToolUse hook (`gsd-context-monitor.js`) reads it and re-warns the agent only every 5 tool calls, except a WARNING→CRITICAL escalation bypasses the debounce and fires immediately.
6. **PID-lockfile + status-file pattern for hook-triggered background work** (`gsd-graphify-update.sh` + `hooks/lib/gsd-graphify-rebuild.sh`) — the lock is written *synchronously in the parent hook* before it returns (eliminating a start/finish observation race), staleness is checked via `kill -0`, and a status JSON records `running`/`ok`/`failed` + duration for any observer to poll.
7. **Opt-in-by-config-presence for all "community" hooks** — every non-default hook is a hard no-op unless `.planning/config.json` sets an explicit flag (`hooks.community: true`, or a two-flag AND-gate for graphify), so new/experimental hooks ship silent-by-default across every existing install.
8. **Hook self-versioning + staleness detection** — every hook file carries a `// gsd-hook-version: {{VERSION}}` header; a background worker diffs each installed hook's header against the current release and surfaces a "stale hooks, reinstall" warning via the statusline/banner.
9. **Atomic staged-write-then-rename for hook publishing** (`scripts/build-hooks.js`) — per-process-PID staging directory on the *same filesystem* as the destination (so POSIX `rename(2)` is atomic), plus a pre-copy `vm.Script` syntax check so a broken hook can never ship (grounded in a real past incident, #1107 et al.).
10. **Workflow-boundary guard mapped to an org rule** — `gsd-workflow-guard.js` detects a direct file edit happening outside an expected orchestration context (no subagent/task session) and nudges toward the correct command. The detection shape — "is this edit happening inside a properly-delegated context?" — is a near-direct fit for enforcing Beamix's existing Layer Contract rule that C-suite/leads must never touch `.ts/.tsx/.sql` directly.
