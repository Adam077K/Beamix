via the Workflow runtime, not automatically on every PR — it is a tool available to QA-Lead, not a gate that
fires by itself. I mark rules "ENFORCED (qa.js, on-demand)" separately from rules enforced automatically.

- **ENFORCED (fully or with only a narrow gap): 9** — rows 1 (partial), 4 (partial), 11, 13, 15, 19-negative-control via 32, 26 (partial), 30 (partial), 32.
- **UNENFORCED — MECHANIZABLE: 40** — the port-target list. Highest-value items, in priority order:
  1. **Row 31 — wire `schema-lint.js` into CI.** The checker's logic already exists and covers ~14 distinct sub-rules (frontmatter completeness, model validity, worker/Task exclusion, isolation rules, length caps, skill-reference integrity) in one shot — but it does not currently pass (16 pass · 10 fail · 5 warnings, exit 1; all 10 failures the single `maxTurns=50 outside range [5,30]` check). Wiring it in requires resolving that first; the resolution chosen was to widen the linter's bound rather than clip the 10 agents' turn allowances (a turn cap is a method constraint, and the locked principle is to constrain outcomes, not methods). Still the single highest-leverage fix in this inventory once that's done.
  2. **Rows 5, 6, 7, 8, 9 — no CI job runs `tsc`, `eslint`, `pnpm test`, `pnpm build`, or `pnpm audit` at all.** The entire QA gate today is a `grep` for a hand-typed string (row 1); zero actual code verification happens automatically anywhere in this repo's CI. This is the largest single gap in the whole system.
  3. **Row 3 — `full`-tier floor is advisory-only in `qa-lead-pass.yml`; only `irreversible` hard-fails.** A trivial one-branch extension of already-working code.
  4. **Row 47 — migration-file SQL linting** (DROP COLUMN, missing RLS, missing FK indexes, plpgsql/DECLARE) is a narrow, parseable grammar with zero current coverage, guarding the highest-blast-radius file class in the repo.
  5. **Row 19 — no hook blocks committing directly to `main`,** despite this being the single most-repeated rule in the entire agent roster (13 of 13 worker files state it near-verbatim).
- **UNENFORCED — INHERENTLY-JUDGMENT: 14** — rows 24 (general case), 28, 33, 37, 43, 45, 55, 58, 60, and the judgment-half of rows 35/36/46/52/57.

Anyone relying on the `DECISIONS.md` entry as ground truth would believe a stronger guarantee exists than actually does.
