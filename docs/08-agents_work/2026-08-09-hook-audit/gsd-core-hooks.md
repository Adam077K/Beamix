# gsd-core Hook Library Audit

**Source:** `~/VibeCoding/_reference/harness/open-gsd_gsd-core/` (read-only reference repo)
**Scope:** every executable hook file under the repo (`hooks/*.js`, `hooks/*.sh`, `hooks/lib/*.js`, `hooks/lib/*.sh`, `scripts/build-hooks.js`) — 31 files, all examined.
**Purpose:** catalogue what exists so Beamix can decide what to port into `.claude/hooks/` (currently empty). Judged against Beamix's actual stack: Claude Code, bash + node, macOS/darwin, git worktrees, Next.js/TypeScript monorepo, pnpm.

## Wiring method (how this was determined)

GSD ships multiple runtime adapters (Claude Code, Cursor, Windsurf/Cascade, Codex, Kimi, …) from one hook source tree. For **Claude Code** specifically, the authoritative registration file is `hooks/hooks.json` (read in full) — it wires **11 of the 31 files** to Claude Code lifecycle events (`SessionStart`, `PreToolUse`, `PostToolUse`, `SubagentStop`, `Stop`, `PreCompact`, `FileChanged`). Cursor and Windsurf wiring is generated at install time by `bin/install.js` from `capabilities/{cursor,windsurf}/capability.json` (both read) using camelCase event names (`sessionStart`, `preToolUse`, …) — confirmed by header comments inside each `gsd-cursor-*.js` / `gsd-windsurf-*.js` file itself, cross-checked against `bin/install.js`'s `GSD_CURSOR_*_HOOK_SCRIPT` / `GSD_WINDSURF_*_HOOK_SCRIPT` constants and the `managedHookEvents` list in `capabilities/cursor/capability.json`.

**Important finding — 5 files are shipped but NOT wired for Claude Code:** `gsd-workflow-guard.js`, `gsd-validate-commit.sh`, `gsd-session-state.sh`, `gsd-phase-boundary.sh`, and `gsd-graphify-update.sh` are copied onto disk (confirmed present in `tests/fixtures/install-tree/claude.json`'s file inventory, and `bin/install.js:11274` explicitly warns if any go missing from the copy step) and each contains a header comment claiming a specific event (`PreToolUse`/`PostToolUse`/`SessionStart`), and product docs (`docs/COMMANDS.md`, `docs/ARCHITECTURE.md`, `docs/FEATURES.md`) describe them as gated behind `hooks.community: true` / `graphify.auto_update: true` in `.planning/config.json`. But `hooks/hooks.json` — the actual Claude Code registration file — does **not** list any of these 5, and no code path in `bin/install.js` was found that conditionally injects them into a user's `settings.json`/`hooks.json` based on those config flags. Their internal self-gating logic (`if hooks.community !== true, exit 0`) is real, but self-gating only matters if the harness invokes the script in the first place — and for Claude Code, nothing was found that makes that happen. Marked **"not wired (Claude Code)"** below; the doc claims are reported as doc claims, not verified behavior.

`docs/ARCHITECTURE.md`'s hook table also states `gsd-validate-commit.sh` fires on `PostToolUse` — this conflicts with the script's own header comment (`PreToolUse hook: … Blocks git commit commands … exit 2`), which is the only reading that makes semantic sense (a `PostToolUse` hook cannot prevent a commit that already happened). Trusted the source over the doc; flagged inline in the table.

## Patterns worth stealing (mechanisms, not vibes)

1. **Curated-file shrink guard** (`gsd-write-guard.js`) — block a whole-file `Write` when new/old line-count ratio drops below a threshold (40%) on a closed path allowlist, with a floor-line exemption and a single-use, path-bound, TTL-expiring sentinel-file escape hatch (plus a plain env-var hatch for interactive use).
2. **Worktree path-containment guard** (`gsd-worktree-path-guard.js`) — compare `git rev-parse --show-toplevel` of the edit target against the active worktree's own toplevel to catch a worker editing the main checkout instead of its worktree; scoped by a branch-name allowlist so it only fires inside agent-managed worktrees.
3. **PostToolUse injection/exfiltration scanner** (`gsd-read-injection-scanner.js`) — regex+heuristic scan of `Read`/`WebFetch`/`WebSearch` output for injection phrasing, invisible Unicode, and credential-bearing or `javascript:`/unsafe-`data:` markdown links; advisory by default, config-gated hard block only above a severity threshold.
4. **Context-budget nudger** (`gsd-context-monitor.js` paired with `gsd-statusline.js`) — a statusline process writes token-usage metrics to a per-session bridge file; a `PostToolUse`/`Stop`/`PreCompact` hook reads it and injects escalating WARNING/CRITICAL text into the *agent's own context* (not just the visible status bar), debounced by tool-call count with a severity-escalation bypass.
5. **Shared git-subcommand classifier** (`lib/git-cmd.js`) — one token-walk parser, reused by multiple hooks, that correctly detects a specific git subcommand through `-C path`, leading env-var assignments, and full-path binaries, closing gaps a naive regex leaves open.
6. **Detached background rebuild after commit** (`gsd-graphify-update.sh` + `lib/gsd-graphify-rebuild.sh`) — PID-locked, config-gated, default-branch-only detached subprocess that rebuilds a derived artifact after a HEAD-advancing git op, writing a `running`→`ok`/`failed` status sidecar file the next agent step can poll; returns instantly and never blocks the triggering tool call.
7. **FileChanged hot-reload with a diff summary** (`gsd-config-reload.js`) — scoped to one exact config path, injects a human-readable summary of what changed as `additionalContext` so a mid-session edit doesn't need a session restart to take effect.
8. **Fail-closed-on-cannot-verify doctrine** (`gsd-agent-isolation-guard.js`, `gsd-cursor-subagent-start.js`) — explicit design rule that a guard which cannot determine whether an invariant holds must deny, not default to "looks safe"; applied consistently on both the fast (cached-sentinel) and slow (re-derive from registry) code paths.
9. **Effective-state verification over flag-trusting** (`gsd-cursor-subagent-start.js`) — instead of trusting a caller-supplied "isolated" flag, the guard independently re-derives whether the dispatch target is *actually* running isolated before allowing it, closing the gap where a model simply omits the flag.
10. **Documented, narrow, auditable escape hatches** (`gsd-write-guard.js` design note) — every hard-block hook ships a bypass that is (a) named in the block message, (b) scoped to exactly one target, and (c) either interactive-only (env var) or single-use/TTL-bound (sentinel file) — deliberately avoiding an undocumented bypass that gets discovered once and then used as a blanket disable.
