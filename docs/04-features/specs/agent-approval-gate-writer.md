# Approval-Gate Writer Agent — PRD

## Purpose

The Approval-Gate Writer is the agent that turns finished work into a **1-click approve/reject card** delivered into the customer's weekly digest and approval queue. Per locked decision #2, schema/citations/listings/scans publish automatically — but **content publishing, email-as-them outreach, and any YMYL-flagged work require explicit customer approval before push.** This agent owns the UX text + email-body draft that becomes that approval card.

The problem it solves: customers won't read PRs, diffs, or technical descriptions. They want a single card that says: *"We wrote this. It will publish to your blog on Tuesday. Here's why it's good for AI search. Approve or change in one click."* If the card text is robotic, they reject by reflex; if it sets up the value clearly in their voice, they approve at >70%.

The agent's deliverable is **not** the underlying content (that's the Content/FAQ writer or the outreach Email-as-them template) — it's the **card framing + the email-body draft when the work is outreach.** It packages someone else's work for human approval.

## Tier availability

All tiers. Approval gates exist on every tier, only the **default approval mode** changes:

| Tier | Default approval mode |
|------|----------------------|
| Starter | Auto on schema/citations/scans; 1-click digest required on content + outreach |
| Growth | Same |
| Scale | Same |
| Professional | Same + auto-approve threshold customizable (e.g. "auto-approve any blog with confidence >0.9") |

YMYL content (medical/legal/financial claims) is **always_human** regardless of tier or customer preference. Brand-Brief Manager enforces.

## Wave

**Wave 2.** Depends on Brand-Brief Manager (Wave 1) being live + Approval Queue UI (frontend, Wave 1 or early Wave 2).

## Inputs

1. **Underlying artifact** (content draft, outreach email body, FAQ block — generated by Content/FAQ writer or outreach generator)
2. **Customer's Brand Brief** (latest canonical version + version_id) — for tone of the approval card
3. **Customer's approval_style** (from brief — informs framing)
4. **Why-this-matters context** (from the generating agent — what AI-search-visibility outcome this drives)
5. **Publish target metadata** (where it will go: WordPress / Shopify / SendGrid sub-account / etc + scheduled time)
6. **Risk flags** (YMYL? competitor-named? geographic-claim?) from the generating agent
7. **Historical approval-rate** for this customer + artifact type (for confidence calibration)

## Outputs

### 1. Approval Card

UI block delivered to `/dashboard/approvals` with:

```json
{
  "approval_card_id": "uuid",
  "customer_id": "uuid",
  "artifact_id": "uuid",
  "artifact_type": "blog_post | faq | outreach_email | schema_change | citation_outreach",
  "title": "string (max 60 chars, customer-voice headline of the card)",
  "value_one_liner": "string (max 140 chars — why this matters for them)",
  "preview": "string (first 300 chars of underlying artifact OR full email body)",
  "publish_target": "string (e.g., 'your blog at /resources, Tuesday 10am ET')",
  "risk_flags": ["string"],
  "approve_action": {"label": "Looks good — publish", "endpoint": "POST /api/approvals/:id/approve"},
  "change_action": {"label": "Change this", "endpoint": "POST /api/approvals/:id/change", "field_options": [...]},
  "reject_action": {"label": "Skip this one", "endpoint": "POST /api/approvals/:id/reject"},
  "deadline_iso": "timestamp — auto-publish or expire if not actioned",
  "auto_action_on_deadline": "publish | skip",
  "card_generated_against_brief_version_id": "uuid"
}
```

### 2. Email-body draft (when artifact_type is outreach)

When the underlying work is an outreach email "as them" (citation request, partner outreach), the Approval-Gate Writer drafts the **full email body in the customer's voice**, including subject, greeting, body, signature. Customer 1-click approves or edits inline.

### 3. Rejection-reason capture template

If customer clicks Change or Skip, render a structured reason picker:

- Doesn't sound like us → routes to Brand-Brief Manager as correction signal
- Wrong target page / wrong recipient → routes to Content/FAQ or outreach gen for regen
- Factually wrong → routes to Adam (≤50) / system flag with hold
- Wrong timing → routes to scheduler
- Not interested → routes to artifact deprioritization

### 4. Digest insertion

Approval cards are bundled into the weekly digest (Digest Writer consumes). Open cards >7 days old escalate to top of digest with "deadline" framing.

## Prompt outline

```
SYSTEM PROMPT — Approval-Gate Writer v1

You write the 1-card framing that turns generated work into a customer's
1-click approve/reject decision. You are NOT the work itself. You are the
package.

YOUR JOB
Take an underlying artifact (blog draft, FAQ block, outreach email, schema
change) and produce:
1. A 60-char title in the customer's voice
2. A 140-char value-one-liner: WHY this matters for THEIR AI-search visibility
3. A preview snippet (300 chars or full email body if outreach)
4. An approve/change/reject action set with appropriate copy

INPUTS
- Underlying artifact + artifact_type
- Customer's Brand Brief (canonical version + version_id)
- Publish target + scheduled time
- Risk flags from the generating agent (YMYL, competitor-named, etc)
- Customer's historical approval rate (calibrate confidence)

VOICE RULES
- Voice canon Model B: the card itself reads "Beamix" (singular). The
  underlying artifact reads "the customer" (their voice).
- Plain English. No jargon. No "AI search visibility metrics improved by..."
  — say "more people will see you when they ask ChatGPT about [topic]."
- One sentence per idea. Active voice. No exclamation marks unless the
  customer's voice samples use them.
- Title = headline. Value-one-liner = the WHY. Preview = the WHAT.

OUTREACH-SPECIFIC RULES (when artifact_type='outreach_email')
- The email body MUST be in the customer's voice, signed by the customer.
- The card framing on top ("Here's an email we'd like to send for you to
  [recipient]") is in Beamix's voice.
- Include the recipient name + relationship context above the body preview.
- Default deadline 48h; auto_action_on_deadline = 'skip' (NEVER auto-send
  outreach without explicit approval).

YMYL RULES
- If risk_flags contains 'ymyl', set approve_action to require an extra
  confirmation step ("I confirm this content is accurate for my practice").
- Card title must mention "Medical claim — review carefully" or
  "Legal advice content — review carefully" verbatim.

NEVER
- Never auto-approve outreach emails. Never. Even if customer has set
  auto-approve threshold high.
- Never reveal you are an agent. Card framing says "we" (Beamix), never "I".
- Never publish a card without `generated_against_brief_version_id` set.
- Never invent the value-one-liner. Pull from the generating agent's
  why-this-matters context.

OUTPUT
Return the approval_card JSON in the exact schema in agent-approval-gate-writer.md.
```

System-prompt total ~390 words.

## Eval criteria

Risk tier **Full**. Customer-trust surface — bad card framing kills approval rate, kills outcomes, drives refunds.

| Rubric | Pass threshold |
|--------|---------------|
| **Title clarity** | ≥4/5 on "Could a non-expert customer understand what's being approved?" (sample audit) |
| **Voice fidelity** | Card voice = Beamix; artifact voice = customer. Cross-contamination = automatic fail |
| **YMYL framing** | 100% of YMYL artifacts have explicit "review carefully" title prefix |
| **Outreach auto-send guard** | Zero outreach emails auto-sent on deadline expiry. 100% require explicit approve. (Automatic fail if violated.) |
| **Approval rate (post-customer #20)** | ≥70% of cards approved on first view. <40% triggers Brand-Brief Manager drift check |
| **Rejection reason capture rate** | ≥90% of rejections include a structured reason |
| **Brief-version traceability** | 100% of cards have `card_generated_against_brief_version_id` populated |
| **Deadline default sanity** | Content default 7 days; outreach default 48h; never 0 |
| **Customer voice non-substitution** | Outreach emails preserve customer's voice samples verbatim where applicable; no Beamix-voice intrusion |

## Dependencies

- **Brand-Brief Manager** (read canonical brief)
- **Content/FAQ writer + outreach generator** (provide artifact + why-this-matters)
- **Approval Queue UI** (`/dashboard/approvals`) — frontend-engineer scope
- **Digest Writer** (consumes open cards for weekly digest)
- **approval_cards table + approval_actions table** (DB)
- **Inngest events**: full lifecycle (card_created → approved/rejected/expired)
- **Resend** for outreach-email previews + dispatch (post-approval)

## Failure modes & fallbacks

| Failure | Fallback |
|---------|----------|
| Card generation fails (LLM error) | Fall back to template-based card with artifact metadata only; flag `card_generated_template_fallback=true` for Adam review |
| Customer never opens digest | After 7 days, escalate to in-app banner; after 14 days, Customer Success Agent reaches out |
| Outreach email auto-action_on_deadline misconfigured to 'publish' | Schema check at write time — REJECT row, emit alert. Tier-floor: critical. |
| Customer mass-rejects 10+ cards in a row | Auto-pause downstream artifact generation, trigger Customer Success Agent intervention |
| Brief version_id missing | Reject card generation; surface to ai-engineer alert (system bug) |
| YMYL flag missed by generating agent but caught by Approval-Gate Writer | Apply YMYL framing automatically; emit `ymyl_flag_late_catch` event for upstream agent calibration |

## Risk tier

**Full.** Touches money-flow adjacency (outreach as them → reputation risk → churn → refund), YMYL content gating, and the primary customer-trust UX surface.
